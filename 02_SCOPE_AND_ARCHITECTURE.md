# Scope and Architecture

Use after choosing the project.

> 好，我决定做这个项目。
>
> 现在仍然不要写代码。
>
> 如果你是负责 review 这个项目的 senior engineer，请帮我把它压缩成一个适合 3 小时 coding interview 的 implementation scope。
>
> 请给我：
>
> 1. Core user flow
> 2. Must-have requirements
> 3. Nice-to-have requirements
> 4. Explicitly out-of-scope items
> 5. Minimal API / interface design
> 6. Minimal data model
> 7. Recommended architecture
> 8. Technology stack
> 9. Minimal project structure
> 10. Testing strategy
> 11. Deployment strategy
> 12. Main failure cases / edge cases
> 13. Security basics worth implementing now
> 14. Production concerns that should NOT be implemented now
> 15. Code-review trade-offs I should be ready to explain
>
> Constraints:
> - strict 3-hour limit
> - single engineer with AI-assisted development
> - must remain understandable and explainable
> - avoid unnecessary infrastructure
> - prefer a working vertical slice early
> - deployment may take extra time because the environment is unfamiliar
>
> 请明确指出：
> - 哪里可能 over-engineer
> - 哪里可能 scope 太薄
> - 哪些东西应该留到 production discussion
>
> 请用中文详细解释，不要开始写代码。

## Architecture review after you propose your own plan

> 这是我目前的 architecture：
>
> [PASTE PLAN]
>
> 先不要改代码。
>
> 请以 senior engineer 的角度 review：
> - correctness
> - simplicity
> - unnecessary complexity
> - deployment risk
> - testability
> - failure handling
> - production trade-offs
>
> 把问题分成：
> 1. 必须现在改
> 2. 建议现在改
> 3. 不要现在实现，只在 code review 讨论
