# 模拟题 5：短链服务 + 点击分析

## 1. 题目

实现：

```text
long URL
→ short code
→ redirect
```

并记录简单 analytics：

- click count
- recent clicks
- user agent
- referrer

## 5. 为什么既存 click_count 又存 clicks

如果只存 clicks：

```text
每次 stats 都 COUNT(*)
```

规模大时会越来越贵。

如果只存 counter：

```text
没有明细 analytics
```

MVP 同时保存：

```text
click_count
+ recent click records
```

production 再做更好的聚合。

## 6. Short Code

本 demo：

```text
uuid4().hex[:7]
```

生成后检查 collision。

这是 prototype 够简单的实现。

Production 可以讨论：

- random base62
- sequence → base62
- hash
- collision retry
- hot key

## 7. Redirect Path

```text
GET /abc1234
→ 307 Redirect
```

为什么不默认 301？

301 更容易被浏览器/CDN长期缓存，之后改变目标会不方便。

307 对 prototype 更安全、可解释。

## 8. Analytics 会不会拖慢 redirect？

会。

本 demo 同步：

```text
lookup
→ increment counter
→ insert click
→ redirect
```

Production 更合理：

```text
fast redirect path
→ emit click event asynchronously
→ analytics pipeline
```

因为 redirect latency 往往比 analytics 强实时更重要。

## 13. Code Review 高频问题

### 百万 QPS？
redirect mapping 放 cache / edge，不要每次直打主数据库。

### analytics 怎么扩？
异步 event ingestion + aggregation。

### code collision？
retry generation；更大规模可用 base62 encoding。

### 恶意 URL？
URL validation + reputation/safe browsing + abuse control。

### 为什么同步写 click？
prototype 简单；production 会把 analytics 从 redirect hot path 解耦。
