# 模拟题 4：Webhook 可靠投递服务

## 1. 题目

实现一个 webhook service：

- 注册 webhook subscription
- 收到 event
- 找到匹配的订阅
- 向目标 URL 投递
- 记录每次 delivery
- 失败后允许 retry

核心对象：

```text
Subscription
Event
Delivery
```

## 2. 三小时 MVP

核心 API：

```text
POST /subscriptions
POST /events
GET  /deliveries
POST /deliveries/{id}/retry
```

## 3. 数据模型

### Subscription

```text
id
event_type
target_url
```

### Event

```text
event_id UNIQUE
event_type
payload
created_at
```

### Delivery

```text
id
event_id
subscription_id
target_url
status
attempts
response_code
last_error
```

## 4. 为什么 event_id UNIQUE 很重要

上游可能因为 timeout 重发相同 event。

如果不 dedupe：

```text
一个业务事件
→ 两次 /events
→ 两次 webhook delivery
```

所以 MVP 加：

```text
event_id UNIQUE
```

这是低成本、高价值的 reliability 设计。

## 5. 正确的数据流

```text
Producer
  ↓
POST /events
  ↓
persist event
  ↓
find subscriptions
  ↓
create pending delivery rows
  ↓
send webhook
  ↓
update delivered / failed
```

为什么要 **先创建 delivery 记录再发送**？

如果先 send：

```text
send 成功
→ process crash
→ 没写 delivery record
```

系统会失去审计信息。

## 6. Demo 如何避免依赖外网

为了练习稳定，本 demo 的 `client.py` 支持：

```text
mock://success
mock://fail
```

这样能稳定演示：

- delivered
- failed
- retry

如果 target URL 是真实 HTTP/HTTPS，则用 `httpx.post()`。

这也是一个很好的 architecture 点：

> external dependency 被封装在 client.py，而不是散落在 endpoint 中。

## 7. Reliability

MVP 实现：

- event idempotency
- pending delivery 持久化
- attempts
- failed status
- manual retry
- timeout

Production 讨论：

- exponential backoff
- jitter
- worker queue
- DLQ
- webhook signing
- secret rotation
- replay tooling
- per-destination rate limiting

## 8. Webhook Signature

Production 常见：

```text
signature = HMAC(secret, raw_payload)
```

Header：

```text
X-Webhook-Signature
```

三小时如果题目没明确要求 security，不需要先做完整 secret management；放在 code review 很合理。

## 11. Code Review 高频问题

### target 很慢？
timeout + async worker，不阻塞 ingestion。

### target 返回 500？
retry with exponential backoff + jitter。

### 永远失败？
max attempts + DLQ / dead delivery + manual replay。

### 如何保证顺序？
如果产品要求顺序，需要 per-destination ordering/partitioning；不是所有 webhook 系统都必须全局有序。

### 如何防伪造？
HMAC signature + timestamp + replay protection。
